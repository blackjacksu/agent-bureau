## Verdict (pre-registered: faster median + success within 5pts of B)

- **Overall: MCP (B) wins.** Warm: B 77% success at 16 ms / 250 tokens. Best crawl arm (C1/C2) reaches only 52% success — outside the 5-point band on every scope except shadesoflight.com — so its 1 ms warm medians do not count as wins overall. Cold: B 18 ms vs C1 299 ms.
- **Per site:** shadesoflight.com — C1/C2 **win** on warm runs (80% vs B 75%, 1 ms vs 16 ms) via the cached sitemap jump, a legitimate warm-agent effect declared in the method; cold crawl still loses. carparts.com — A0 (naive!) beats B on time (54 ms vs 450 ms) and stays inside the success band (85% vs 90%), so it scores a narrow WIN on this site — at 310k tokens per task, roughly 1,200x B's cost. paulaschoice.com — all crawl arms 0%: category navigation from the homepage does not reach product targets within 6 steps; MCP 65% stands alone.
- **Tokens are not close anywhere:** MCP 232–268 median vs crawl 83k–573k. Speed was the crawl arm's only theoretical opening, and it wins it only warm, on one site, via sitemap reuse.
- **Follow-ups (filed from ablation, not tuned speculatively):** (1) B on carparts.com costs ~450 ms/query because matching loads the full 7,475-node graph per query — a pgvector NN query in PgStore is the known fix and would likely erase the A0 time win; (2) crawl arms need a search-template win on paulaschoice-style catalogues (search jump found no usable result links there); (3) warm-cache token accounting now counts ingestion on hits — keep it that way.
